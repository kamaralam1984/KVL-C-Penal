## Frontend (Node): npm audit
Tool: `npm audit --json` in `frontend/` (first run with a 300 s limit timed out; the second, 500 s run completed).
Result: **16 moderate, 0 high, 0 critical** advisories. All are in the **development linting toolchain** (`eslint`, `eslint-config-next`, `@typescript-eslint/*`, `eslint-plugin-*`) and trace back to one root cause: `minimatch` has a potential denial of service via glob-part amplification (affects `eslint` and `eslint-config-next`, the two direct dev dependencies). No advisory affects the runtime packages (`next`, `react`, `framer-motion`, `recharts`, `radix-ui`, `lucide-react`, `next-themes`) in this run.
Remediation: upgrade `eslint`/`eslint-config-next` when a release resolves the `minimatch` range; `npm audit fix --force` would be a breaking major change and was **not** applied. Risk is limited to developer machines and CI processing untrusted glob patterns, which this repo does not do.
